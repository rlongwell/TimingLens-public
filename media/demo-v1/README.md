# TimingLens demo v1

A 4:25 narrated engineering demo: what to bring, how the tool uses evidence, and what a defensible result looks like. The finished movie is `TimingLens-demo.mp4` (1920 × 1080, 30 fps, H.264/AAC). English captions are optional, with SRT/VTT sidecars. The media sources archive retains the original voice, real GUI recording, edit instructions, diagrams, score generator, and experimental evidence.

## Story and evidence

The first 98 seconds explain the input contract, local analysis, and the four priority-selector structures. The remaining walkthrough uses a real TimingLens Qt window: matching inputs, analysis, measured path, source correlation, recommendation, reviewed diff, isolated build, Experiment Lab, regression checks, and portable export. Build footage is visibly accelerated. Navigation pauses and the export file picker are trimmed. Zooms restore the source window's aspect ratio; cursor endpoints follow recorded clicks, with four popup coordinates corrected from the observed GUI actions.

The fresh sweep is `priority-20261117T054822Z-f51443e2`: one original and three candidate implementations, using Vivado 2024.2, the same Default recipe, xc7z020clg400-1, a 2 ns clock, and the standalone N=16 priority example. Every candidate passed its actual Yosys equivalence gate (67 matched points) and the runner's baseline/candidate simulations before implementation. The original build is explicitly reused for the later variants.

The RTL proof covers binary inputs and corresponding register states for N=16; it is not a four-state, power-up, or implemented-netlist equivalence claim. Concept diagrams show RTL structures, not an asserted post-route topology. TimingLens uses deterministic local analysis; the AI production credits refer to making this film.

The board and active hash work were not accessed or changed. Product code was not edited for the video. Recording-only palette/font settings and the example sweep live in this production workspace.

## Rebuild the film

Run from the extracted archive root (or the TimingLens repository root). The archive preserves `media/demo-v1` and `work/demo-video-v1` relative paths. Linux prerequisites: Python 3.12, FFmpeg/ffprobe, Lato fonts, and DejaVu Sans Mono. The pinned Python package versions are in `requirements.txt`.

```bash
python3 -m venv work/demo-video-v1/.venv
work/demo-video-v1/.venv/bin/pip install -r media/demo-v1/requirements.txt
mkdir -p work/demo-video-v1/render work/demo-video-v1/stills
OPENBLAS_NUM_THREADS=1 work/demo-video-v1/.venv/bin/python media/demo-v1/score.py
OPENBLAS_NUM_THREADS=1 work/demo-video-v1/.venv/bin/python media/demo-v1/edit.py
OPENBLAS_NUM_THREADS=1 work/demo-video-v1/.venv/bin/python media/demo-v1/mix.py
work/demo-video-v1/.venv/bin/python media/demo-v1/captions.py
work/demo-video-v1/.venv/bin/python media/demo-v1/finalize.py
work/demo-video-v1/.venv/bin/python media/demo-v1/verify_export.py
```

The original TTS MP3 and word timestamps are retained, so rerendering requires no provider login, paid voice generation, model download, or Vivado rerun. `transcribe.py` documents the optional local Whisper transcription step. `record_gui.py` documents capture but is not required to reproduce the edit. Fresh capture requires TimingLens and PySide; fresh experiment validation requires the TimingLens repository and its toolchain. `audit_evidence.py` was run against TimingLens itself and its result is included as `evidence-audit.json`.
